Project title:  
Machine Learning Regime Dynamics in Multi-Asset Execution
Project description – background, aims, objectives, research question(s), brief reflection on novelty/originality
Background
Cryptocurrency markets are strongly non-stationary: any single trading logic, mean-reversion (grid) or momentum (trend), is profitable only inside the regime it was designed for and bleeds capital outside it. Static single-strategy systems are structurally fragile, suffering from regime dependence, concept drift, systemic BTC–altcoin correlation, and fee drag. This fragility motivates regime-aware execution, where the system classifies the current market state and routes orders to the strategy best suited to that regime. Classical approaches model regimes as latent, unlabelled states via Hidden Markov Models (HMMs) or Gaussian Mixture Models (GMMs); this project instead uses a supervised Random Forest classifier on pre-labelled regimes, RANGING (mean-reverting / low-volatility), TRENDING (momentum / directional), and DANGER (crisis / high-volatility), a deliberate design choice that yields interpretable, confidence-calibrated routing signals. To the best of our knowledge, no existing open-source framework treats regime state as a first-class, machine-learned routing signal and benchmarks reinforcement learning (RL) execution policies against a supervised routing baseline under realistic transaction costs. The central research contribution is therefore not the trading framework itself, which serves as the experimental apparatus, but the rigorous empirical comparison of RL agents (DQN, PPO, and optionally a Decision Transformer) against the supervised regime-routing baseline, with profitability treated as a motivating domain constraint rather than a claimed result.
Aims
This project builds a multi-engine algorithmic trading framework as the experimental apparatus for a controlled comparison of reinforcement learning execution policies against a supervised regime-routing baseline. The framework integrates a calibrated Random Forest regime classifier with four specialised execution engines, routing capital to the strategy best matched to the predicted regime, RANGING (mean-reverting / low-volatility), TRENDING (momentum / directional), or DANGER (crisis / high-volatility), for each trading pair, supervised by a portfolio-level risk layer and a cross-asset BTC correlation gate. The supervised baseline, validated via walk-forward backtesting, serves as the control condition. The research contribution is the empirical benchmark: training DQN and PPO agents within a faithful simulation environment and measuring whether learned policies improve risk-adjusted return and maximum drawdown over the supervised baseline, with the Decision Transformer as an explicit stretch goal.
Objectives
Build and calibrate a per-pair Random Forest regime classifier (3 classes, 14 technical features, isotonic probability calibration, walk-forward validation), benchmarked against an HMM/GMM baseline to validate the supervised design choice.
Implement four specialised execution engines, Grid, Trend, Swing, and Mean-Reversion, each gated by the classifier's regime prediction and confidence score; characterise strategy redundancy via pairwise return correlation as a standalone secondary finding.
Engineer a hybrid Rust + Python production stack with CI/CD, Docker deployment on AWS EC2 (Tokyo), and a faithful Python simulation environment validated against the production Rust engine on deliberately off-baseline action sequences, not only the baseline path.
Develop a cross-asset BTC correlation gate that suppresses altcoin exposure during systemic DANGER (crisis / high-volatility) states.
Validate the supervised routing baseline via walk-forward out-of-sample backtesting as the central evaluation and guaranteed-complete core (Phase 0–1), reporting effective fold count, sample-size limits, and statistical-power constraints honestly.
Train DQN and PPO agents as the deliverable RL comparisons within the simulation environment, building any offline dataset (for the Decision Transformer stretch chapter) from diverse trajectories, perturbed/ε-greedy baseline rollouts, random-policy rollouts, and DQN/PPO training logs, rather than baseline replays alone.
Run must-do experiments on ETH-USDT and BNB-USDT; treat DOGE-USDT and XRP-USDT as no-edge stress tests if time allows. Apply Bonferroni correction across all RL-vs-baseline comparisons, pre-registering a non-significant result as a valid finding.
Consider a pooled multi-pair RL agent (pair-ID in observation vector) as a data-efficiency comparison against per-pair agents.
Research Question
Can reinforcement learning agents (DQN, PPO) learn a regime-switched multi-engine execution policy that outperforms a calibrated supervised routing baseline on risk-adjusted return and maximum drawdown, when both operate within a shared execution environment under realistic transaction costs, and, if not, what does a non-significant result reveal about the sufficiency of supervised regime routing?
Hypotheses:
System-Level Hypotheses (validated by the supervised baseline):
SH1: The regime-gated hybrid framework exhibits lower maximum drawdown than standalone Grid or Trend strategies.
SH2: The BTC cross-asset risk gate reduces systemic exposure during DANGER (crisis / high-volatility) states.
SH3: Confidence-weighted sizing (Kelly-like scaling) improves risk-adjusted return versus fixed sizing.
Comparison-Level Hypotheses (central thesis):
CH1: At least one RL agent (DQN or PPO) achieves a statistically higher risk-adjusted return (Sharpe ratio) than the supervised routing baseline on walk-forward out-of-sample data, after Bonferroni correction for multiple comparisons.
CH2: RL agents exhibit lower maximum drawdown than the supervised baseline during regime transitions.
CH3: A non-significant result across all RL-vs-baseline comparisons, after correction, is a valid finding documenting where supervised routing suffices.
Novelty and Originality
The project’s originality lies in two areas: (1) the use of regime classification as a first-class, calibrated routing signal, not a post-hoc filter, for multi-engine execution, with an HMM/GMM baseline validating the supervised design choice and honest documentation of both positive and negative results; and (2) a rigorous supervised-vs-RL benchmark, measuring whether DQN and PPO agents can learn policies that outperform the supervised baseline within the same execution environment, with pre-registered non-significant results treated as valid findings. The three-regime taxonomy (ranging, trending, danger) follows established market-microstructure convention; the contribution is the calibrated routing mechanism and the controlled empirical comparison, not the taxonomy itself.
Methodology – rationale, data selection and collection, recruitment of participants, analytical process 
Rationale
This project follows a design-science research methodology: the primary artefact is a multi-engine trading framework that serves as the experimental apparatus for a controlled RL-vs-supervised comparison. Evaluation is quantitative (risk-adjusted return, drawdown, Sharpe ratio), measured first against static single-strategy baselines (system-level validation) and then as a head-to-head RL-vs-supervised-baseline comparison under realistic transaction-cost assumptions.
Data Selection and Collection
Historical OHLCV candlestick data (1-hour resolution) from Binance for BTC-USDT, ETH-USDT, BNB-USDT, XRP-USDT, and DOGE-USDT, spanning January 2025 to May 2026 (~12,360 bars per pair).
Real-time WebSocket price feeds and order-book snapshots from Binance and Gate.io during paper-trading deployment.
No human participants are involved; all data is publicly available market data and social-media trade calls.
Feature Engineering
Fourteen technical indicators are computed in Rust from raw OHLCV data: returns, volatility ratio, normalised ATR, trend strength, RSI-14, volume ratio, close-location value, ADX-14, MACD histogram, distance to VWAP, OBV rate of change, Choppiness Index, Fractal Dimension Index, and Aroon Oscillator. These serve as input features for the regime classifier.
Regime Labelling and Model Training
Regime labels, RANGING (mean-reverting / low-volatility), TRENDING (momentum / directional), DANGER (crisis / high-volatility), are assigned using a forward-looking dynamic threshold (k·ATR/close), adapting to each asset's volatility rather than a fixed percentage move. A Random Forest classifier is trained per pair with class-weighting to up-sample the rare DANGER class. Probability calibration uses CalibratedClassifierCV (isotonic for n≥500, else sigmoid, 5-fold).
Validation Methodology
Chronological 80/20 train–test split (standard k-fold is invalid on overlapping, label-leaking financial time series).
TimeSeriesSplit cross-validation for hyperparameter selection.
Walk-forward backtesting (January 2025–May 2026, 1-hour bars) with transaction costs modelled at 0.2% round-trip.
Live paper-trading validation on Binance testnet and Gate.io paper since 8 May 2026, collecting realised PnL per engine.
Statistical benchmarking: Sharpe ratio, maximum drawdown, and win rate versus HODL and single-strategy baselines. Walk-forward out-of-sample validation is the central test of the thesis and is prioritised accordingly. Effective fold count and sample-size limits will be reported honestly, with statistical-power constraints stated rather than concealed.
Diebold–Mariano significance tests for pairwise comparisons (supervised vs. each RL agent), with Bonferroni correction across 12 planned comparisons (4 agents × 3 metrics). A non-significant result is pre-registered as a valid finding.
Analytical Process
Evaluation follows a three-stage pipeline: (1) held-out classification metrics (accuracy, per-class F1, feature importances) to assess the regime classifier; (2) backtest PnL simulation with realistic fees to measure each engine's edge; and (3) live paper-trading PnL collection to bridge the backtest-to-live realism gap (instant-fill bias, slippage). An August go/no-go decision gates any live micro-stake deployment.

Theoretical framework and intended tools/technologies
Theoretical Framework The project is grounded in two complementary theoretical frames:
Regime-switching models of financial markets. Market microstructure theory holds that asset returns are generated by latent regimes (trending, mean-reverting, crisis) whose transitions are non-stationary. Hidden Markov Models (HMMs) and Gaussian Mixture Models (GMMs) are the classical probabilistic approach, learning latent unlabelled states from observed data. This project makes a deliberate, different design choice: a supervised Random Forest classifier trained on pre-labelled regimes where the labels are defined by a forward-looking dynamic threshold. The supervised approach sacrifices HMMs’ ability to discover novel regimes in exchange for interpretable, calibrated routing signals; isotonic probability calibration ensures confidence scores are well-calibrated for downstream position sizing. An HMM/GMM baseline is included to validate this trade-off empirically.
Markov Decision Process (MDP) formulation for optimal execution. The regime-switched execution problem is formally cast as an MDP: state sₜ = (14-feature regime vector + inventory + unrealised PnL + time); action aₜ = (engine selection + position size); reward rₜ = (realised PnL − fees − slippage − λ·drawdown penalty + β·shaping bonus, following Ng, Harada & Russell 1999). The supervised hybrid policy approximates π(a|s) with deterministic rules modulated by the calibrated classifier and serves as the control baseline. DQN and PPO agents are trained online within the simulation environment to learn π directly; the Decision Transformer (stretch goal) is trained offline, with its dataset built from diverse trajectories, perturbed/ε-greedy baseline rollouts, random-policy rollouts, and DQN/PPO training logs, to avoid imitating the baseline alone.
